# 故障排查（V2）

> 先确认状态：DSH 设置 → 远程控制。提交问题时提供状态布尔值、错误文字、发生时间与设备/浏览器版本；**不要提供** Cookie、Authorization、配对码、完整公网地址或 DSH 对话内容。

本页按「症状 → 可能原因 → 检查 → 解决」组织。所有排查都优先使用只读、安全、可恢复的步骤；不要一上来就删目录、杀进程或重装。

---

## 一、插件 / 设置入口

### `127.0.0.1:3080` 无法访问

- **原因**：通常是承载 `dsh web` 的终端被关闭（DSH 是前台 Web 服务进程）。
- **检查**：独立终端重新运行 `dsh web`，先确认电脑本机能打开 3080。
- **解决**：保持该终端打开（可以最小化）；关闭终端或 `Ctrl+C` 会结束 3080。

### 设置页没有「远程控制」

- **原因 1**：插件未安装或未生效。
- **检查/解决**：运行 `dsh plugin --profile web add dsh-remote-web-gateway` 后**重启 DSH Web**。
- **原因 2**：安装到了错误的 Profile。
- **检查**：确认安装命令里的 `--profile web` 与你的 DSH Web Profile 一致（隔离环境可用 `dsh web` 启动后查看页面源码 `__DSH_BOOT__` 中是否出现 `dsh-remote-web-gateway`）。
- **原因 3**：DSH Web 未重启，插件未加载。
- **检查/解决**：完全重启 DSH Web 后再进设置页。
- **原因 4**：插件包安装异常（如 tarball 解压后 package.json 带 BOM / 损坏，导致 DSH 解析失败）。
- **检查**：查看插件目录下的 `package.json` 是否能被正常解析（首字节不应为 BOM `EF BB BF`；用 JSON 解析器验证）；查看 DSH 本地日志中的插件加载报错。
- **解决**：重新安装插件包（先卸载再安装），不要手工改 DSH 源码。

### 插件安装 / 加载出现难以解释的问题

- **先确认 DSH 本体状态**：如果插件安装或加载出现难以解释的错误，请先确认 DeepSeek Harness 本体是官方、未修改的版本（例如没有被本地手工修改、第三方补丁或其它插件改动）。
- **建议**：在官方、未修改的兼容版本上复现后再报告问题；报告时注明 DSH 版本与是否使用过任何第三方改动。

## 二、开启远程控制失败

设置页「诊断信息」只显示稳定错误码与二进制来源，请照抄：

| 错误码 | 含义与处理 |
|---|---|
| `config-conflict` | 检测到已有 Cloudflare Tunnel 配置（`~/.cloudflared/config.yml` 等）。Quick Tunnel 无法在此配置下启动；**我们没有修改你的配置**。处理：先确认该配置是否属于你正在运行的其他隧道，确认真实冲突后再临时移走该配置并重试 |
| `binary-rejected` / `checksum-mismatch` / `size-mismatch` / `version-mismatch` | cloudflared 校验失败。缓存损坏会自动删除重下；若仍失败，检查网络能否访问 GitHub release。自动模式下会尝试下一个下载源（镜像始终经过与官方源相同的完整校验，镜像只是传输路径，绝无绕过校验） |
| `download-failed` | 无法下载 Cloudflare Tunnel（所有可用网络路径均已尝试）。下载期间设置页显示实时进度与当前路径/源（「通过系统代理 · 官方源」等）；只要进度仍在增长就不会超时中断。自动模式下官方源若持续过慢（约 15 秒窗口内平均低于可用水平），会显示「官方源下载较慢，正在尝试备用镜像…」并自动切换已验证的备用镜像继续下载。处理：检查网络，或在设置页「下载设置」调整下载网络/下载源后重试 |
| `proxy-invalid` / `proxy-connect-failed` | 代理配置无效 / 无法通过代理连接官方源。检查「下载设置」里的自定义代理地址，或确认系统代理/环境变量代理可用（代理地址绝不会包含账号密码，也不支持在设置中保存账号密码，请使用 `HTTPS_PROXY` 环境变量） |
| `start-timeout` / `exit-before-ready` / `spawn-failed` | 隧道建立超时/启动失败，重试；持续失败看电脑网络/防火墙是否阻止 cloudflared 出站 |
| `connection-lost` | 隧道建立后连接断开，公网入口已关闭 |
| `internal` | 发生未预期的内部错误。请查看「诊断信息」中的稳定错误码后重试；原始原因保留在本地日志 |
| `unsupported-platform` | 当前平台无对应 asset / 无法运行（平台未映射，或该平台 asset 无法解压为可执行文件）。macOS x64/arm64 已在 v0.2.2 支持（`.tgz` 固定版本 + SHA-256 校验后解压并 `--version` 复验）；darwin 真机端到端仍待人工验收 |
| `startup-failed` | 插件启动失败（状态文件损坏等，fail closed），查看 DSH 本地日志 |

### cloudflared 下载很慢 / 官方源无响应

- **检查**：设置页下载阶段显示「已下载 X / Y · 速度 · 当前网络方式 · 当前下载源」。
- **解决**：保持「下载网络 = 自动（推荐）」；自动模式依次尝试 自定义代理 → 环境变量代理（`HTTPS_PROXY`/`HTTP_PROXY`，只读）→ Windows 系统代理（如 Clash）→ 直连。官方源持续过慢时自动切换到已验证备用镜像，无需人工干预。
- 不要自己到 GitHub 找 exe；不要关闭验证标准。

### 检测到已有 Cloudflare 配置（`config-conflict`）

- **不要**看到提示就直接删除自己的 Cloudflare 配置文件。
- 如果你的电脑本来就在运行其它 Cloudflare Tunnel（如 Named Tunnel），Quick Tunnel 确实无法共存。
- 确认真实冲突后，再临时移走该配置并重试；本项目不会修改你的配置。

### 代理相关

- 自定义代理只支持 `http://` / `https://` 地址，不接受账号密码（请用 `HTTPS_PROXY` 环境变量）。
- 自动模式未识别到系统代理时：确认 Windows 系统代理已启用（HKCU Internet Settings），或直接选用「直连」。

## 三、Tunnel 与配对

### 二维码不出现

- **原因**：Tunnel 尚未 Ready。开启后你会依次看到「正在准备安全连接… / 正在检查 cloudflared… / 正在创建 Cloudflare Tunnel… / 正在启动安全连接… / 正在等待公网地址… / 正在建立安全连接…」，第一次使用还可能有下载阶段。
- **检查**：状态是否停留在「正在建立安全连接…」超过约 60 秒（默认 Ready 超时）。
- **解决**：继续等待；超过超时后重试。**二维码只在 Tunnel Ready 后出现**——hostname 拿到不等于 Ready。

### 二维码出现以后手机打开 Cloudflare 1033

- **原因**：正常版本二维码只在 Cloudflare Edge 确认隧道可访问之后才显示，1033 不应再作为正常流程出现。
- **处理**：若仍偶发，等 1-2 秒手动刷新一次（Cloudflare 边缘抖动），不会反复出现；若持续 1033，回电脑**停止远程控制**再重新开启一次；仍复现则记录电脑端显示阶段并报告。

### QR / 配对码显示「设备已成功配对」，二维码不见了

- **原因**：正常。Pairing Ticket 是一次性的，已被使用。
- **解决**：连接第二台设备时点击「**生成新的配对码**」。

### 显示「配对码已过期」

- **原因**：正常。一次性配对凭证默认 5 分钟有效。
- **解决**：点击「**生成新的配对码**」重新配对。

### 手机扫码 / 输入配对码失败

- 配对码 5 分钟过期：点击「生成新的配对码」；
- 页面显示「设备已成功配对」但手机仍提示无效：该凭证已被使用（一次性），点击「生成新的配对码」；
- 已授权设备达到上限（默认 20 台）：在电脑设置页撤销一台再试；
- 提示「尝试过于频繁」：稍等再试（全局限速）。

### 第二台设备怎么连

- 第一台配对成功后，点击「生成新的配对码」→ 第二台设备扫码 / 输入新 8 位码 → 完成独立授权。每台设备都有自己的 Device Session。

### 被撤销的设备仍能访问？

- 撤销是持久化且立即生效的；若仍能访问，检查是否撤销了错误的设备（按名称/UA 核对）。

### 停止后旧地址还能打开？

- 不应能。停止/崩溃会先清除公网来源，旧 URL 应失效；重新开启后地址会变化。若旧地址仍返回内容，立即停止并报告。

## 四、更新

### 「检查更新失败，请稍后重试」

- **原因**：你安装的版本未发布到 registry / GitHub，或 npm 与 GitHub 都当前不可达（v0.2.2 起 npm 不可达会回退 GitHub Releases 作为只读信号，仅当两者都不通才提示）。
- **处理**：手动再点「检查更新」；不影响当前已安装版本继续运行。

### 「更新已安装，需要重启 DSH 后生效」

- 重启 DSH Web 即可。插件不会偷偷重启你的 DSH。

### 更新失败

- 更新失败不会替换当前版本：当前版本继续运行，重试即可。

## 五、停止 / 重启 / 孤儿进程

### 停止远程控制

- 设置页「停止远程控制」（连接建立中为「停止」）→ 隧道停止、地址失效、当前配对凭证立即作废。
- 重新开启会得到**新的公网地址**与**一张全新的初始配对码**。

### 如何判断是否有 cloudflared 孤儿进程（只读）

- 停止远程控制后，在 Windows 上可用只读命令检查是否还有残留的 cloudflared 进程：

```powershell
Get-Process cloudflared -ErrorAction SilentlyContinue | Select-Object Id, StartTime, Path
```

- 若发现残留进程且不是你自己在用的其它隧道：先记录进程启动时间与路径，确认属于本插件后再考虑处理；不要凭猜测结束不明进程。
- 正常停止流程会先关闭公网入口再结束进程，不会留下孤儿；若发现异常残留，请把现象与时间记录到报告。

## 六、手机 / 平板界面

V2 移动层：只有明确手机启用 Phone UI；平板（含 iPad）与桌面使用 DSH 原生界面。遇到布局问题先记录设备型号/系统/浏览器/截图，再决定是否调整；不要用关闭认证或把 DSH 绑到 `0.0.0.0` 的方式绕过。
